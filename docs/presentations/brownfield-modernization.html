Roadmap Governance

Unblocked modules go first; engineering setup and spec work run side by side.

Stages 2 & 3: Plan & Orchestrate

Bounded Tracks, Isolated Worktrees, Routed Models

Each track has a fixed scope, its own workspace, and a model sized to the work.

Bounded Tracks

  • Each track owns one Area: directory.
  • Edits outside that area are rejected.
  • Each track maps to requirement IDs.

Worktree Isolation

  • One Git worktree per track.
  • Parallel work without branch contention.
  • Downstream tracks unlock as upstream merges.

Model Routing

  • Track complexity sets the reasoning tier.
  • No under-powered retry loops.
  • No premium models on boilerplate.
Stage 4: Execute

Code Traced Back to the Spec

Every requirement is tagged from spec to test and audited before ship.

Test First

A failing test tagged with the requirement ID comes before any implementation.

specs trace Gate

Every scenario must map to a test. Gaps block ship.

Verification

Independent Review, Recorded in a Ledger

Every finding gets a documented decision.

Independent Review

  • A separate reviewer agent checks the diff.
  • Findings are logged with line and risk.
  • Review cycles are capped.

Every Finding Resolved

  • Fix: correct and re-verify.
  • Dispute: show why the code is right.
  • Defer: record an issue or waiver.
Rule: No track closes with open findings.

Quality Engineering

Focused QA with gin-qa

Test what the requirements say, and re-review only what changed.

The Test Generation Trap

Unconstrained AI produces hundreds of low-value tests, and QA drowns in triage.

The Fix: Generate tests only from formal requirements, at the depth qa/guidelines.md sets.

Hash-Pinned Drift Detection

Each case pins its requirement's hash. gin-qa cases plan reports:

  • missing: new requirements.
  • stale: changed requirements.
  • obsolete: deleted requirements.
Token Economics & Governance

Token Economics: Three Levers

Spend early on clarity, route by complexity, and audit locally.

1. Shift Left

Clarifying specs costs far less than late rework rippling through legacy modules.

2. Complexity Routing

The right model tier per track means fewer retries and less overspend.

3. Local CLI Audits

Lint, trace, hash, and gate checks run locally at zero token cost.

Principle: A small token investment up front prevents large downstream rework and retry costs.
Stage 5: Ship

Ship Safely, Keep Specs Alive

Release and spec update happen in one step.

The Ship Gate

  1. Full tests, lint, typecheck, and specs trace.
  2. specs archive merges the delta into spec.md.
  3. The change folder moves to the archive.
  4. Integration PR needs QE approval.

Long-Term Health

  • docs/specs/ stays the source of truth.
  • Legacy paths retire as modules ship.
  • Regression tests preserve business logic.
