# Design: CodeGraph documentation and install hints

Date: 2026-10-05
Status: confirmed in conversation on 2026-10-05
Workflow ID: codegraph-docs-hints

## Goal and Scope

CodeGraph is used by the stage contract, four agents (`agent-researcher`, `developer`, `code-reviewer`, `docs-writer`), `tech-doc`, `setup`, and `doctor`, but neither `README.md` nor `docs/` mentions it. The 2026-10-01 project-profile-bootstrap design made it "recommended, optional with grep/read fallback"; this change documents that decision and adds two small hints. No new dependencies, no change to lifecycle gates.

### A. Documentation

1. **New page `docs/guides/recommended-tools.md`** with:
   - **CodeGraph** section: what it gives agents (symbols plus call paths in one lookup instead of grep/read loops); install (`curl -fsSL https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.sh | sh`, Windows `irm https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.ps1 | iex`, or `npm i -g @colbymchenry/codegraph`); MCP wiring with `codegraph install` (one global run covers every project); per-repository index with `codegraph init`, which `/gin-workflow:setup` offers on brownfield/legacy repositories; where gin-workflow uses it (stage contract lookup rule, the four agents, `tech-doc`, `doctor` stale-index warning with `codegraph sync`); and the known limitation below.
   - **Known limitation, worktrees:** a git worktree has no `.codegraph/` of its own, so agents working there fall back to grep/read. The main checkout's index is not used there because it reflects another branch. Users who want an index in a worktree run `codegraph init` inside it and `codegraph uninit -f` before removing it, because an untracked `.codegraph/` makes `git worktree remove` fail.
   - **Other optional tools** table, moved from the README "Optional, per feature" sentence: `codex` or `agy` (multi-provider routing, link `concepts/providers.md`), `gh` or `glab` (team mode, link `guides/team.md`), Node with `@playwright/test` 1.49 or later (QA end-to-end specs, link `guides/qa.md`). Each row: tool, used for, install hint, link.
2. **`README.md`:** the "Optional, per feature" sentence adds CodeGraph and links to the new page; the Documentation table's Guides row adds "recommended tools".
3. **`docs/getting-started.md` §1 Prerequisites and `docs/huong-dan.md` §1 Chuẩn bị:** one line pointing to the new page (Vietnamese in `huong-dan.md`).

### B. Behavior hints

1. **`setup` skill, Quick setup step 5 (Code index):** when the stage is brownfield or legacy and `codegraph.installed` is false, print one line suggesting CodeGraph with a link to `docs/guides/recommended-tools.md`. No question, no install, never blocks setup. The existing `codegraph init` offer when installed but not indexed is unchanged.
2. **`doctor` (`setup_service.py`):** when `codegraph.installed` is false, `checks_details["codegraph"]["suggestion"]` says CodeGraph is not installed and points to `docs/guides/recommended-tools.md`. The stale-index suggestion is unchanged. The `codegraph` check stays informational; it never fails doctor.
3. **`code-reviewer` agent, Phase 1 step 4:** when `.codegraph/` exists, run `codegraph impact <symbol>` or `codegraph callers <symbol>` for each public symbol changed in the diff; a caller outside the diff that should have changed with it is a finding. Without an index, use grep as today.

Source edits go in `plugins/gin-workflow/src/`; `dist/` is regenerated by the build, not edited.

## Error Handling and Testing

- A new test in `tests/workflow_core/test_setup_cli.py` asserts the doctor `suggestion` when `codegraph` is not on PATH, and that it is absent when installed and fresh. Written first, seen failing.
- Full Python suite and `tests/install_smoke_test.sh` after rebuilding `dist/`.
- Docs: every new relative link resolves to an existing file.

## Out of Scope

- Indexing worktrees automatically (`codegraph init` in `bootstrap`, daemon cleanup). Investigated: `codegraph uninit` does not stop the per-worktree MCP daemon and `git worktree remove --force` leaves it orphaned until its idle timeout (5 minutes by default, verified); handling that needs coupling to CodeGraph's internal `daemon.pid`. Deferred until usage data shows the benefit.
- `codegraph sync` before agent lookups (the MCP server's file watcher keeps the index fresh).
- `codegraph affected` in verify.
- Measuring CodeGraph usage in `report`.
- rtk.
