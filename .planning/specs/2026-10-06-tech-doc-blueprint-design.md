# Design: tech-doc project blueprint — `FEATURES.md` and `API.md`

Date: 2026-10-06
Status: confirmed in conversation on 2026-10-06
Workflow ID: tech-doc-blueprint

## Goal and Scope

The `tech-doc` skill writes eight files that describe a repository by layer (stack, architecture, structure, ...). It has no feature-oriented view: no catalog of features, no list of the backend endpoints the repository exposes, and no mapping from a feature to the frontend screen, the endpoint it calls, the backend handler, and the data it touches.

Add two canonical files to the split documentation set, `FEATURES.md` and `API.md`, so a reader can answer "what does this product do, which endpoints exist, and which files do I touch to change feature X". The change is limited to the skill text, two new templates, one template edit, docs, and packaging tests. No new Python code.

## Components

| Component | Change |
|---|---|
| `plugins/gin-workflow/src/templates/codebase/API.md` | New template. Standard header (`Analysis Date`, `Scope`, `Evidence`, `Index Use`), then `## Conventions` (base path, versioning, auth scheme, error format; short), `## Endpoints` (grouped by module, one table per module: `Method \| Path \| Handler (file:line) \| Auth \| Summary \| Feature`), `## Other Interfaces` (GraphQL operations, WebSocket channels, inbound webhooks, gRPC services, when present), `## Completeness Check`, `## Inference And Uncertainty`, `## Follow-up`. |

## Behavior (skill flow additions)

1. **Gather endpoints.** Use `codegraph explore` first when `.codegraph/` exists. Otherwise, or to verify, grep the route declarations of the frameworks present (for example Express/Fastify routers, NestJS decorators, FastAPI/Flask decorators, Django `urls.py`, Rails `routes.rb`, Next.js route handlers and server actions). If the repository ships an OpenAPI or GraphQL schema, link it from `API.md` and still list the compact table.
2. **Gather frontend calls.** Find routes and screens (router config, file-based routes) and the calls they make (`fetch`, axios, generated API clients, GraphQL hooks). Match each call to an endpoint by method and path.
3. **Write `API.md`, then `FEATURES.md`.** Every row cites `file:line`. A cell inferred without a citation is marked as inference, never presented as verified.
4. **Completeness check.** Record in `API.md` → `## Completeness Check` the search method used, the number of route declarations it found, and the number of table rows; explain any difference. Record in `FEATURES.md` → `## Coverage Gaps`: endpoints with no frontend caller, frontend calls with no matching endpoint, and features missing one side. Serious gaps (for example a frontend call to a missing endpoint) also go to `CONCERNS.md`.

## Edge Cases

| Case | Behavior |
|---|---|
| No HTTP or RPC API (CLI, library) | `API.md` is not written. `FEATURES.md` uses commands or public functions as the `Entry point`, drops the Frontend and API columns, and states why in one line. |
| Backend only | `FEATURES.md` Frontend cells are `—`; `Coverage Gaps` lists only feature-level gaps. |
| Frontend only (calls third-party APIs) | `API.md` is not written; the called APIs belong in `INTEGRATIONS.md`; the API column names the external endpoint. |
| Subsystem scope | Only that subsystem's endpoints and features, in the existing `<scope-slug>/` subfolder. |
| Very large API surface | Every endpoint is still listed, grouped by module; summaries stay one line. |

## Testing

- `gin-workflow specs template codebase/API.md` and `gin-workflow specs template codebase/FEATURES.md` print the new templates.
- `tests/workflow_providers/test_harness_packaging.py` passes with the two templates added; full `tests/test_all.py` passes; `tests/install_smoke_test.sh` passes after rebuilding `dist/`.
- Manual: run `/tech-doc` on a full-stack repository (qwikfone) and check that `API.md` lists its endpoints with handlers and auth, `FEATURES.md` maps features across FE → API → BE → data, and gaps are reported. Run it on gin-workflow (CLI) and check that `API.md` is not written and `FEATURES.md` uses commands as entry points.

## Out of Scope

- A CLI or static parser that extracts routes.
- Request and response schemas or field lists in `API.md`.
- Fixing the gaps the check reports.
- Changes to the other six codebase files beyond the `OVERVIEW.md` link.
