# Fixes for issues #30-#38 (patch 3.5.4)

Epic: gin-workflow-5crd
Kind: technical
Points: 8 (9 bug fixes in 10 modules of gin and gin-qa, 4 skills, 1 new trace flag; medium: workspace and team cross-repository paths)
Status: confirmed by the user on 2026-11-26.

## Goal and scope

Fix the nine open GitHub issues #30-#38 and release them as patch 3.5.4. Each was reproduced by reading `master` 54facb29 (after 3.5.3); every cited cause is still in the code.

| Issue | Defect | Cause on master |
|---|---|---|
| #30 | `gin team check-plan` and `record plan-approved` reject a track that changes the workspace parent | `team.py` `_repo_findings`: no `Repo:` is `missing Repo:`, `Repo: .` is not in `workspace.repos` |
| #31 | commit-msg shim fails every commit where `.githooks/commit-msg` is absent or not executable | `team_init.py` `SHIM` runs `exec "<top>/.githooks/commit-msg"` with no existence check |
| #32 | `gin specs status` reports `none` on Gitea for a merged PR whose head branch was deleted | `hosts/gitea.py` `pr_for_branch` matches `head.ref` only; Gitea then reports `refs/pull/<n>/head` and keeps the name in `head.label` |
| #33 | gin-qa ignores the worktree when `qa.e2e` points into a workspace child, and the e2e save step fails | `gin_qa/reqs.py` resolves `qa.e2e` against the main checkout; `/gin-qa:e2e` step 10 passes paths of two repositories to one `gin commit` |
| #34 | `gin reviewer --base` fails for a workspace child track | `reviewer.py` `route` runs `git diff <base>...HEAD` in the gin root (the parent) |
| #35 | Every SDD plan gets topic `04-plan`, so lane and parent topic branches of different epics share names | `team_pending.py` `topic_of` takes the plan file stem |
| #36 | `gin specs lint --change --against` fails every later PR of a change once its spec merged | `specs.py` `_feature_diagram_findings` requires an activity diagram changed in the current diff for every `ADDED` capability; `changed_since` diffs two-dot |
| #37 | `gin specs trace` at ship reports child-repository REQs `missing` before the lane merges | `specs_trace.py` `req_sources` lists only the child's checkout under the gin root, never a lane branch; from a linked parent worktree the child is `skipped` |
| #38 | A gate waived with `gin unblock` is not shared to the epic bead in team mode | `lifecycle_cli.py` `_unblock_command` writes the local event only; `_SHARED_EVENTS` has no `gate.waived` |

In scope: the nine fixes, their regression tests, the docs and skill text each fix changes, and the 3.5.4 release.
Out of scope: other team-mode or workspace changes; renaming lane branches of epics already in flight; making `gin commit` split paths per repository.

## Approach

One epic, one fix per issue, each in the module named above. Fixes are independent; none changes a JSON field that gin-console reads.

- **#30 parent tracks.** `Repo: .` names the workspace parent. The plan parser and the track bead's `Repo:` line read `.` as no repository, which every later step (`_track_repo`, lane checks) already treats as the parent. `_repo_findings` accepts a track without `Repo:` (or with `Repo: .`) when every listed file lies in the parent (`space.repo_of(item) is None`), and reports each file that lies in a child as `` `<file>` is in repo <child>; set Repo: <child> ``. A track whose files span the parent and a child still fails. `skills/team/references/workspace.md` and the plan template say `Repo: .` names the parent.
- **#31 shim.** The shim exits 0 when the tracked hook is missing and runs it with `sh`, so a lost executable bit does not matter:
  `hook="$(git rev-parse --show-toplevel)/.githooks/commit-msg"; [ -f "$hook" ] || exit 0; exec sh "$hook" "$@"`.
  `install_hook` already rewrites a shim it owns, so `gin team hooks` upgrades old installs; the release notes say to rerun it.
- **#32 Gitea head.** `pr_for_branch` takes the branch from `head.label` when `head.ref` starts with `refs/pull/`, without an `owner:` prefix. This covers every caller (`specs status`, lane PR lookup, `team complete`, `team_pending`).
- **#33 gin-qa e2e in a child.** In `gin_qa/reqs.py` `locate`, when `qa.e2e` lies inside a `workspace.repos` child and the current directory is in a worktree of that child, `e2e_dir` (and `package_dir`) are rebased onto that worktree, the way `workspace.qa_root` does for a `shape: qa` child. Cases, guidelines, runs and evidence stay in the QA home. `/gin-qa:e2e` step 10 and the `qa-track` skill group the paths by repository and run one `gin commit` per repository, and report each commit.
- **#34 reviewer diff.** `gin reviewer` gains `--worktree <path>`: the diff runs there; without it, in the gin root as today. The review skill passes the lane worktree for a track whose `Repo:` is a child. Config is still read from the gin root.
- **#35 topic.** `topic_of` returns the change folder name (`<epic>-<slug>`) when the lead plan is the SDD `04-plan.md`, so lane branches become `feat/<epic>-<slug>-<lane>` and the parent branch `feat/<epic>-<slug>`. The date-stem rule for `.planning/plans/<date>-<topic>.md` is unchanged. Epics already in flight are not migrated (decided in discuss): the release notes tell them to finish on 3.5.3 or rename their lane branches.
- **#36 lint against.** With `--against`, the "activity diagram added or changed" rule applies only when the change's `02-spec-delta.md` itself was added or changed since the merge base, i.e. the PR that adds the `ADDED` blocks. `changed_since` diffs against `git merge-base <ref> HEAD`, so a later base commit no longer changes the result. The use-case and decision-label rules keep their current scope.
- **#37 trace lane refs.** `gin specs trace` gains a repeatable `--ref <repo>=<ref>` (decided in discuss): for that child, the test files and their text come from `git ls-tree -r <ref>` and `git show <ref>:<path>` in the child's checkout. From a linked worktree of the parent, a child is found through the parent's main checkout instead of being `skipped`. The `sdd` skill's ship step passes `--ref <repo>=<lane branch>` for each unmerged lane in team mode. An unknown repo or unresolvable ref exits 2 with the name.
- **#38 shared waivers.** In team mode with Beads, `gin unblock` of `requirement_confirmed` or `plan_approved` also writes `gates.<gate> = {waived: true, reason, waived_by, at}` to the epic bead (via `write_gate`); `orchestration-ready` mirrors local waivers of those gates the same way. `gin state` reads such an entry as a waiver (`waived(<reason>)`), not as a PR proof. If no epic bead is found, the waiver stays local and the command warns, as `_share_gate` does for proofs.

## Risks and rollback

- #35 changes the lane branch name of SDD epics in flight; a claim after the upgrade creates a new branch. Mitigated by the release note; no data is lost, the old branch stays on origin.
- #36 relaxes a CI check; a spec PR that adds `ADDED` blocks is still checked as before.
- #38 writes a new kind of entry under the epic bead's `gates`. gin 3.5.3 counts any entry of a gate as met, so a member still on 3.5.3 sees the waived gate as met rather than `waived(...)`; that unblocks them as intended, and only the label differs.
- #31 needs `gin team hooks` rerun in each repository to take effect.
- Rollback: each fix is its own commit; revert it and release 3.5.5.

## Testing

A regression test per issue that fails on master and passes after the fix: check-plan with a parent track (no `Repo:`, `Repo: .`, mixed parent and child files); the shim run with the hook missing and with mode 644; Gitea `pr_for_branch` with a `refs/pull/<n>/head` payload; gin-qa `locate` from a child worktree and the per-repository commit in the skill text check; `gin reviewer --worktree` on a child repository; `topic_of` for SDD and legacy plan paths; lint `--against` on a plan-only PR after the spec merged, and on a branch behind the base; trace with `--ref` and from a linked parent worktree; unblock then `gin state` reading the shared waiver from the bead. Then the full suite (`python3 -m pytest -n auto`), and before the tag the suite with `bd` off `PATH`.
