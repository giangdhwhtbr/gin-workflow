# Design: `describe` skill — HTML view of a bead or epic

Date: 2026-10-05
Status: confirmed in conversation on 2026-10-05
Workflow ID: describe-skill

## Goal and Scope

Add a read-only `describe` skill to gin-workflow that writes one self-contained HTML file for a bead or epic. The page has a fixed template with two columns: the left column draws the bead's graph, the right column shows every Beads field of the selected bead. It follows the `report` / `gin-workflow usage` pattern: a thin skill that calls a deterministic CLI subcommand which reads `bd`.

Data comes from Beads only. Review-ledger state, gate state, waivers, spec/plan evidence, and `ai_usage` are out of scope.

## Components

| Component | Role |
|---|---|
| `plugins/gin-workflow/src/skills/describe/SKILL.md` | Standard "Before you start" block (config check, stage contract). Runs `gin-workflow describe <id>`, reports the output path and node count. Read-only, never opens a browser, never chains into another stage. |
| `plugins/gin-workflow/src/scripts/workflow_core/describe.py` | `collect(repo, root_id, max_nodes=300)` → graph; `layout(graph)` → assigns `x`, `y` to every node; `render(graph, template_text)` → HTML string. Has its own small `_bd()` helper (same shape as `usage.py`, not imported from it). Raises `DescribeError` (bd failures, unknown bead) and `GraphTooLarge`. |
| `plugins/gin-workflow/src/scripts/workflow_core/describe_cli.py` | `describe <id> [--out PATH] [--format text\|json] [--repository PATH]`. Writes the file atomically via `atomic.py`, creating parent directories and overwriting any previous file. |
| `plugins/gin-workflow/src/scripts/workflow_core/cli.py` | Adds `describe` to the subcommand list, the usage line, and dispatch (same style as `usage`). |
| `plugins/gin-workflow/src/templates/describe.html` | The fixed template: two-column layout (graph left, details right), inline CSS and JS, one placeholder `/*__DESCRIBE_DATA__*/` for the JSON payload. Located with `plugin_templates_dir()`; no project override. |
| Docs | `docs/reference/skills.md` (`describe` entry), `docs/reference/cli.md` (`## \`gin-workflow describe\`` section), README skill list if it enumerates skills. |
| `dist/` | Regenerated by the existing build for claude-code, codex, antigravity; never hand-edited. |

## Data Flow

### Collect

1. `bd show <root> --json --include-comments` for the root bead.
2. **Up:** follow the `parent-child` dependency from `show` output to the top. Only the parent chain is added; siblings of ancestors are not.
3. **Down:** level by level, `bd dep list <id> --direction=up --type parent-child --json` gives children; all new nodes of a level are fetched with a single `bd show <a> <b> ... --json --include-comments`. Depth is unlimited.
4. **Bugs:** for every node in the tree, `bd dep list <id> --direction=up --type discovered-from --json`, one hop. Bugs found this way are fetched with `bd show` but not expanded further.
5. **Blocks:** read `blocks` dependencies from each node's `show` data. An edge is drawn only when both ends are in the graph; an outside bead is listed in that node's `detail.external_blockers` (id, title, status) and not drawn.
6. A `visited` set prevents revisiting nodes (guards against corrupt parent-child cycles).
7. When the node count exceeds `max_nodes` (300), stop and raise `GraphTooLarge` with the count reached.

Exact `bd` JSON field names are confirmed against the installed `bd` during planning; the fake `bd` in tests mirrors them.

### Payload embedded in the HTML

```
{ meta:  {root, generated_at, repo},
  nodes: [{id, title, type, status, priority,
           role: root|ancestor|descendant|bug, x, y,
           detail: {description, design, acceptance_criteria, notes, assignee, labels,
                    created_at, updated_at, closed_at, metadata, comments[],
                    external_blockers[]}}],
  edges: [{from, to, kind: parent|blocks|discovered}] }
```

### Layout (deterministic tidy tree)

- Rows: ancestors above, root at row 0, descendants at rows 1..n.
- A bug is laid out as a child of the node it was discovered from; if discovered from several nodes, it sits under the one with the smallest id and the other `discovered` edges are still drawn.
- Leaves take consecutive x slots; a parent is centered over its children; siblings are ordered by id.
- Same input always yields the same coordinates.

### Rendering

- `parent` edges: straight lines. `blocks`: curved orange arrows. `discovered`: dashed red lines. Node color by status; root highlighted.
- Right column defaults to the root bead. Clicking a node shows that bead's full detail; a "back to root" control returns. Clicking an id in a detail list (children, blockers, bugs) selects that node when it is in the graph.
- Sections with empty values are hidden.
- Text fields (description, design, acceptance criteria, notes, comments) are shown as plain text with `white-space: pre-wrap`; no markdown rendering.
- Safety: the JSON is serialized with `</` escaped as `<\/` before substitution; the JS writes bead data only via `textContent` / SVG text nodes, never `innerHTML`.
- No external resources: no CDN, fonts, or images by URL.

## Output

- Default path: `.agent-workflow/runtime/describe/<id>.html` (already git-ignored via `.agent-workflow/.gitignore`). `--out PATH` overrides it.
- `--format text`: prints the path and node count. `--format json`: `{"status": "ok", "path", "nodes", "edges"}`.

## Error Handling

| Case | Behavior |
|---|---|
| No `.agent-workflow/generated/effective-config.yaml` | Skill stops and asks for `/setup`. The CLI itself does not need config. |
| `bd` missing, failing, or printing invalid JSON | Exit 2, message `bd <cmd> failed: ...`; no file written. |
| Unknown bead id | Exit 2, `bd show <id>: no such bead`; no file written. |
| Graph exceeds 300 nodes | Exit 3, message with the count and a hint to describe a child bead; no file written. |
| Single bead with no relations | Normal output, one-node graph. |
| Parent-child cycle | Each node visited once; no infinite loop. |
| Closed or tombstoned bead | Shown normally; status visible via color and label. |

## Testing

Written first and seen failing, using `unittest` and the fake `bd` from `tests/workflow_core/team_fixtures.py` (`fake_cli`, `path_with`), as in `test_usage.py`.

`tests/workflow_core/test_describe.py`:
- collect: three-level epic yields all descendants plus the parent chain, no ancestor siblings; bugs one hop only; outside blockers go to `external_blockers`, not nodes; a cycle terminates; exceeding a small `max_nodes` raises `GraphTooLarge`; one `bd show` call per level.
- layout: deterministic across runs; parent centered over children; no two nodes share a position; a bug sits below its discoverer.
- render: placeholder replaced; a title containing `</script><img onerror=...>` is escaped; output contains no `http://` or `https://` resource references.

`tests/workflow_core/test_describe_cli.py`: default path and `--out`; `--format json` shape; exit codes 2 and 3.

Existing checks that must still pass: `tests/workflow_core/test_docs_coverage.py` (skill and subcommand documented), the full `tests/test_all.py`, and `tests/install_smoke_test.sh` after rebuilding `dist/`.

Manual: run `gin-workflow describe` on a real epic in this repository, open the HTML, click several nodes, capture a screenshot as evidence.

## Out of Scope

- Review-ledger, gate, waiver, spec/plan, and `ai_usage` data in the page.
- Markdown rendering of text fields.
- Drawing beads outside the graph (external blockers) as nodes; expanding bugs beyond one hop; ancestor siblings.
- A `--depth` flag, project template overrides, opening a browser automatically.
- Sharing `_bd()` with `usage.py`.
