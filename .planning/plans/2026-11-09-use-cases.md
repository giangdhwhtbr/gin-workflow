# Plan: Use cases in living specs and the SRS

Spec: .planning/specs/2026-11-09-use-cases-design.md
Workflow: use-cases

## Objective

A business analyst keeps use cases in `<specs>/<cap>/use-cases/<slug>.md` (SDD layout), `gin specs lint` checks them, `gin specs export` prints them in each SRS chapter, and `gin specs archive` links them in the `spec.md` of a new capability.

**Goal** (spec): a business analyst can write use cases for a capability in the SDD layout, next to its requirements and diagrams, and `gin specs export` prints them in the SRS.

**Architecture**: use cases follow the diagrams model: files edited directly on the spec branch, no ID, no hash, never in `02-spec-delta.md`. Lint lives in `workflow_core/specs.py` next to `lint_diagrams`; the SRS chapter in `workflow_core/specs_export.py:_chapter`; archive linking in `workflow_core/specs_archive.py:81-82`.

**Tech Stack**: Python 3 standard library, unittest/pytest, HTML templates with `{{placeholder}}`.

**Global Constraints** (spec, verbatim):
- Use cases follow the diagrams model: one file per use case, `<specs>/<cap>/use-cases/<slug>.md`, edited directly on the spec branch, no ID or hash, never in `02-spec-delta.md`.
- Use cases are optional: no lint rule requires a capability to have one.
- Lint findings exit 1, as the other lint findings do.
- Existing projects: no new finding unless they add `use-cases/`. A project-overridden `srs-capability.html` keeps working; `customizing-templates.md` documents the new placeholder.
- An existing `spec.md` without `## Use Cases` stays valid.
- `dist/` is regenerated by the build; no hand edits there.

## Route Rubric
- Choose the weakest model that can do the work.
- Raise the model for broad context or design judgement.
- Raise the effort for intrinsic difficulty: intricate logic, many edge cases, or long chains of steps.

| Kind of work | Model | Effort |
|---|---|---|
| Mechanical edits, documentation, boilerplate | weakest | `low` |
| Bounded implementation with a clear spec | middle | `medium` |
| Cross-module change, security, migration, concurrency | strongest | `high` |

Unclear requirements never raise the model or effort.

## Requirement Analysis
- Problem statement: the SDD living spec has requirements, diagrams, and assets, but no place for actor-driven flows, and the SRS cannot show them.
- Success criteria: the acceptance criteria of US-1, US-2, US-3 in the spec pass as tests; `python3 -m pytest -n auto` is green.
- Constraints: Global Constraints above; `skills/sdd/SKILL.md` stays at most 6,000 characters (`tests/workflow_core/test_skill_routing.py`, `test_sdd_discuss_confirms_capabilities_before_ids`); it is 5,941 today.
- Non-goals: `/gin:explain`, the `gin-ba` plugin, the legacy layout, REQ-ID links in the SRS.

## Approach Options
### Option 1: Diagrams model (files, no IDs)
- Summary: one Markdown file per use case, checked by lint, rendered by export, linked by archive for a new capability.
- Pros: reuses the diagram paths through lint, export, and archive; no change to IDs, hashes, delta parsing, trace, or renumber.
- Cons: no per-use-case history in change folders; traceability only through the `Requirements:` line.

### Option 2: Requirement model (UC-IDs through the delta)
- Summary: `UC-<CAP>-NNN` blocks with hashes, ADDED/MODIFIED/REMOVED in the delta, archived into living files.
- Pros: full traceability and change history.
- Cons: touches next-id, hash, renumber, archive, trace, and lint; much larger.

### Recommended Approach
- Selected option: Option 1.
- Rationale: chosen by the user in discuss (2026-11-09); smallest change that meets the goal.

   ```python
   _USE_CASE_REQS = re.compile(r"^Requirements:[ \t]*(.*)$", re.MULTILINE)
   _MAIN_FLOW = re.compile(r"^## Main flow[ \t]*\n(.*?)(?=^## |\Z)", re.MULTILINE | re.DOTALL)


   def _known_req_ids(root: Path, cfg: Mapping[str, Any]) -> set[str]:
       """REQ-IDs in a living spec, or ADDED or MODIFIED in an open change folder."""
       known = set(living_blocks(root, cfg))
       base = changes_dir(root, cfg)
       for change in sorted(base.iterdir()) if base.is_dir() else []:
           if change.is_dir() and change.name != "archive" and change_file(change, "spec-delta").is_file():
               known |= {b.id for b in delta_blocks(root, change)[0] if b.section in ("ADDED", "MODIFIED")}
       return known


   def lint_use_cases(root: Path, cfg: Mapping[str, Any]) -> list[str]:
       """Every `<specs>/<cap>/use-cases/*.md` has a title, an actor, known REQ-IDs, and a numbered main flow."""
       paths = sorted(specs_dir(root, cfg).glob("*/use-cases/*.md"))
       known = _known_req_ids(root, cfg) if paths else set()
       errors: list[str] = []
       for path in paths:
           text, name = _COMMENT.sub("", path.read_text(encoding="utf-8")), shown(root, path)
           if not re.search(r"^# \S", text, re.MULTILINE):
               errors.append(f"{name}: missing '# <use case name>' title")
           if not re.search(r"^Actor:[ \t]*\S", text, re.MULTILINE):
               errors.append(f"{name}: missing 'Actor: <primary actor>' line")
           line = _USE_CASE_REQS.search(text)
           ids = [found.group(0) for found in REQ_ID.finditer(line.group(1))] if line else []
           if line is None:
               errors.append(f"{name}: missing 'Requirements: REQ-…' line")
           elif not ids:
               errors.append(f"{name}: no REQ-ID on its Requirements line")
           flow = _MAIN_FLOW.search(text)
           if not (flow and re.search(r"^\d+\.\s+\S", flow.group(1), re.MULTILINE)):
               errors.append(f"{name}: missing '## Main flow' with a numbered list")
           errors += [f"{name}: {req} is not in a living spec or an open change" for req in ids if req not in known]
       return errors
   ```

   `_COMMENT` is the existing `re.compile(r"<!--.*?-->", re.DOTALL)` at `specs.py:107`. Finding order per file: title, actor, requirements, main flow, unknown REQs; the step-1 tests expect exactly one finding each.
