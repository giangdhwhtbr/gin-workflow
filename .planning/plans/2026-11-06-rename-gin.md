# Plan: Rename: gin CLI, gin: skill namespace, gin:learn

Epic: gin-workflow-rename-gin
Spec: .planning/specs/2026-11-06-rename-gin-design.md

## Objective
`gin` is the only CLI name and `gin:` the only skill, agent, and command namespace. The seven `gin-` prefixed skills drop the prefix (`gin-knowledge` becomes `learn`). No `gin-workflow` alias is installed. Hooks, the `AGENTS.md` block, and `team init` files written under the old name are recognised and rewritten by the new CLI, and `setup doctor` reports what is still on the old name. The installers install `gin` and remove the previous `gin-workflow` install. gin-qa and gin-orchestrator call `gin`. `plugins/*/src`, `tests/`, `README.md`, `AGENTS.md`, and `docs/` use the new names, and a test keeps them from coming back. The plugin version becomes 3.0.0 and the launcher version 3.0.

Architecture: no new module. Program names and markers change in `workflow_core` (`cli.py`, the 16 argparse parsers, `hooks.py`, `agents_block.py`, `team_init.py`, `setup_service.py`), each marker keeping a `LEGACY_*` twin that is recognised and rewritten. The plugin name moves to `gin` in the manifests; the plugin directory stays `plugins/gin-workflow/`, so the installers map the directory to its plugin id (`gin-workflow` to `gin`) and use the id for the launcher and every install target. A one-off sweep script does the mechanical text replacement; a new test (`tests/workflow_core/test_rename_sweep.py`) fails on any old command or namespace left.

Tech stack: Python 3.12 standard library, `unittest` tests run by `python3 -m pytest -n auto`; Bash (`install.sh`) and PowerShell (`install.ps1`) installers with their smoke tests.

Global Constraints (from the spec):
- Clean cut: no `gin-workflow` launcher, `.cmd` shim, or alias is installed.
- Out of scope: renaming the repository, the `plugins/gin-workflow/` directory, the gin-qa or gin-orchestrator plugins, or the release archive name.
- Unchanged: the environment variables `GIN_WORKFLOW_*`, the files `.gin-workflow-src.json` and `gin-workflow-bundle.json`, the marketplace id `gin-workflow-marketplace`, the project state folders `.agent-workflow/` and `.planning/`, the team CI file names `gin-workflow.yml`, and the orchestrator's task-tracking provider id `gin-workflow`.
- History in `.planning/` (specs, plans, knowledge, roadmap) is not rewritten.
- gin-console, `gin-harness/AGENTS.md`, `~/gin-fam/CLAUDE.md`, and other repositories' hand-written files are not changed here; a gin-console bead is created at orchestrate.
- Old markers are recognised and rewritten, never refused: hooks (`generated by gin-workflow hooks install`, `gin-workflow hooks run`), the `AGENTS.md` block (`<!-- gin-workflow:start`, `<!-- gin-workflow:end -->`), and `team init` files (`generated by gin-workflow team init`).
- The installers remove an old `gin-workflow` launcher only when it is the managed one; a foreign file of that name is kept and reported.
- No skill name equals a command name, and the renamed shared skills keep the 6,000-character budget.
- No new dependency. No em or en dashes in new docs text.

## Approach Options
### Option 1: One epic, clean cut, four tracks by file area (chosen in discuss)
- Summary: CLI and user-repository files; plugin identity, skills, add-ons, and the src/tests sweep; installers; docs.
- Pros: each file changes once; one upgrade for users; tracks are reviewable alone.
- Cons: a large sweep; the installer track carries migration risk.

### Option 2: Two epics (CLI first, plugin later)
- Summary: ship `gin` as the CLI, then rename the plugin.
- Pros: smaller first step.
- Cons: the same files change twice; users upgrade twice.

### Option 3: Install a `gin` symlink and rename the plugin, keep the text
- Summary: alias-level change only.
- Pros: tiny diff.
- Cons: contradicts the no-alias decision and leaves the old names in every message.

### Recommended Approach
- Selected option: Option 1.
- Rationale: chosen by the user in discuss on 2026-11-06, with all `gin-` prefixes dropped, no alias, and internal names unchanged.

### Shared tool: the sweep script
Tracks 1, 2, and 4 run this script. It is not committed: save it outside the repository (for example in your scratch directory) as `rename_sweep.py`, and run it with paths relative to the worktree root. It prints each changed file and the count on stderr.

````python
"""One-off rename sweep for gin-workflow-rename-gin: python3 rename_sweep.py <file-or-folder>..."""
import re
import sys
from pathlib import Path

TOP = ("setup", "state", "unblock", "record", "quick-check", "rules", "specs", "docs", "team", "usage",
       "reviewer", "hooks", "evidence", "task", "routes", "notify", "paths", "goal", "worktree", "milestone")
SKILLS = {"gin-knowledge": "learn", "gin-sdd": "sdd", "gin-team": "team", "gin-worktrees": "worktrees",
          "gin-debugging": "debugging", "gin-review-response": "review-response",
          "gin-parallel-agents": "parallel-agents"}
RULES = [
    (re.compile(r"(?<![\w.-])gin-workflow:(?!start|end)"), "gin:"),
    (re.compile(r"(?<![\w./-])gin-workflow(?= (?:%s)\b)" % "|".join(map(re.escape, TOP))), "gin"),
    (re.compile(r"(?<![\w./-])gin-workflow(?= --version\b)"), "gin"),
    *((re.compile(rf"(?<![\w.-]){re.escape(old)}(?![\w-])"), new) for old, new in SKILLS.items()),
]
SUFFIXES = {".md", ".py", ".json", ".yaml", ".yml", ".toml", ".sh", ".ps1", ".txt", ".html", ""}
SKIP_PARTS = {"dist", "__pycache__", ".git"}
# Files that keep old names on purpose (legacy markers, old install paths); edited by hand in their track.
SKIP_FILES = {
    "plugins/gin-workflow/src/scripts/workflow_core/hooks.py",
    "plugins/gin-workflow/src/scripts/workflow_core/agents_block.py",
    "plugins/gin-workflow/src/scripts/workflow_core/team_init.py",
    "tests/workflow_core/test_hooks.py",
    "tests/workflow_core/test_agents_block.py",
    "tests/workflow_core/test_team_init.py",
    "tests/workflow_core/test_rename_sweep.py",
    "tests/install_smoke_test.sh",
    "tests/install_smoke_test.ps1",
}


def files(arg: str) -> list[Path]:
    path = Path(arg)
    found = [path] if path.is_file() else sorted(f for f in path.rglob("*") if f.is_file())
    return [f for f in found if not SKIP_PARTS & set(f.parts) and f.as_posix() not in SKIP_FILES]


changed = 0
for arg in sys.argv[1:]:
    for path in files(arg):
        if path.suffix not in SUFFIXES:
            continue
        try:
            text = path.read_text(encoding="utf-8")
        except UnicodeDecodeError:
            continue
        new = text
        for pattern, replacement in RULES:
            new = pattern.sub(replacement, new)
        if new != text:
            path.write_text(new, encoding="utf-8")
            changed += 1
            print(path)
print(f"{changed} files changed", file=sys.stderr)
````

The script skips `SKIP_FILES`, the same set as `ALLOWED` in `tests/workflow_core/test_rename_sweep.py` (Track 2); those files are edited by hand in Tracks 1 and 3. It changes only commands followed by a known subcommand, `--version`, the `gin-workflow:` namespace (never `gin-workflow:start` / `gin-workflow:end`), and the seven skill names. Prose naming the product (`the gin-workflow plugin`, `plugins/gin-workflow/`) and the internal names of Global Constraints stay. After each run, review `git diff` and fix by hand what reads wrong (for example `the sdd skill` where the sentence needs `the \`sdd\` skill`).
