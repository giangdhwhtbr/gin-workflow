# Plan: Use cases and activity diagrams that match a BA's SRS

Workflow: srs-ba-alignment
Spec: `.planning/specs/2026-11-15-srs-ba-alignment-design.md`

## Objective

The SDD use case and activity templates, `specs lint`, and `specs export` match the SRS a business analyst writes: use cases carry trigger, secondary actors, exception flows, business rules, and include/extend relations; the SRS shows a generated use case diagram per capability; activity diagrams show lanes, labelled decision branches, and the use case they draw; lint asks for a diagram per feature instead of per capability, and skips technical changes.

## Global Constraints

Copied from the spec:

- A use case's slug (its file name without `.md`) is its ID. No `UC-` numbering.
- The use case diagram is generated by `specs export` from the use case files and never stored.
- The new use case lines and sections are optional. Lint checks only that `Includes:`, `Extends:`, and `Use case:` name an existing use case.
- Feature-level lint has two rules: a change updates an activity diagram of each capability it changes, and each use case it adds or modifies is drawn by an activity diagram that names it.
- Lint checks that each edge leaving a decision node has a label.
- A `technical` change skips every change-level diagram and use case rule, including the existing one.
- Revised after a BA review: an included use case needs no `Actor:` and gets no actor edge; the capability rule applies to `ADDED` blocks only; a changed use case needs its own diagram only when it has an alternative or exception flow; activity nodes are declared inside their lanes; actor names match without regard to case or repeated spaces; edges read `«include»`/`«extend»`; actors carry their own class.
- Extended: a change's kind for lint comes from the epic's `kind:` label first, falling back to `Kind:` of `01-proposal.md` when the tracker cannot answer; `specs new --kind`; `discuss` settles the kind of every epic and SDD discuss labels the epic it creates.
- Out of scope: `/gin:explain`, the `gin-ba` plugin, a command that writes the use case diagram, Mermaid syntax checks beyond decision-edge labels, swimlane enforcement, the legacy layout.

## Approach Options
### Option 1: Extend `specs.py` and `specs_export.py` in place
- Summary: add small helpers (`line_value`, `line_values`, `lint_references`, `changed_since`, `unlabelled_decision_edges`, `_feature_diagram_findings`) next to the existing linters, and `use_case_diagram` next to `_chapter`.
- Pros: follows the existing pattern (every SDD linter lives in `specs.py`); one place for readers; tests extend the existing files.
- Cons: `specs.py` grows by about 100 lines.

### Option 2: New module `specs_usecases.py` for use case and diagram rules
- Summary: move `lint_use_cases`, `lint_diagrams`, and the new rules into a new module.
- Pros: smaller `specs.py`.
- Cons: a refactor the spec did not ask for; moves code other modules import (`setup doctor` shares `CAPABILITY_FOLDERS`).

### Recommended Approach
- Selected option: Option 1.
- Rationale: surgical change in the existing pattern; no refactor outside the request.

     def line_value(text: str, key: str) -> str:
         """The value of the first `<key>:` line outside `<!-- -->` comments, stripped; '' when absent."""
         found = re.search(rf"^{re.escape(key)}:[ \t]*(.*)$", _COMMENT.sub("", text), re.MULTILINE)
         return found.group(1).strip() if found else ""


     def line_values(text: str, key: str) -> list[str]:
         """The comma-separated values of the first `<key>:` line, each stripped, empty ones dropped."""
         return [value.strip() for value in line_value(text, key).split(",") if value.strip()]


     def lint_references(root: Path, cfg: Mapping[str, Any]) -> list[str]:
         """`Includes:`/`Extends:` of a use case and `Use case:` of an activity diagram name a use case of the same capability."""
         base = specs_dir(root, cfg)
         errors: list[str] = []
         for cap in sorted(p for p in base.iterdir() if p.is_dir()) if base.is_dir() else []:
             cases = sorted((cap / USE_CASES_DIR).glob("*.md"))
             slugs = {path.stem for path in cases}
             for path in cases:
                 text = path.read_text(encoding="utf-8")
                 for key in ("Includes", "Extends"):
                     for slug in line_values(text, key):
                         if slug == path.stem:
                             errors.append(f"{shown(root, path)}: {key} names the use case itself")
                         elif slug not in slugs:
                             errors.append(f"{shown(root, path)}: {key} names unknown use case '{slug}'")
             for path in sorted((cap / DIAGRAMS_DIR).glob("*-activity.md")):
                 errors += [f"{shown(root, path)}: Use case names unknown use case '{slug}'"
                            for slug in line_values(path.read_text(encoding="utf-8"), "Use case") if slug not in slugs]
         return errors

     def _quoted(text: str) -> str:
         return '"' + text.replace('"', "#quot;") + '"'


     def use_case_diagram(capability: str, folder: Path) -> str:
         """Mermaid flowchart of a capability's use cases: actors outside the system box, include and extend edges.

         Actor names match without regard to case or repeated spaces; the first spelling met labels the node."""
         texts = {path.stem: path.read_text(encoding="utf-8") for path in sorted((folder / "use-cases").glob("*.md"))}
         if not texts:
             return ""
         ids = {slug: f"uc{number}" for number, slug in enumerate(texts, 1)}
         actors: dict[str, tuple[str, str]] = {}

         def actor(name: str) -> str:
             label = " ".join(name.split())
             return actors.setdefault(label.casefold(), (f"a{len(actors) + 1}", label))[0]

         nodes: list[str] = []
         edges: list[str] = []
         for slug, text in texts.items():
             heading = re.search(r"^# (\S.*)$", specs._COMMENT.sub("", text), re.MULTILINE)
             nodes.append(f"    {ids[slug]}([{_quoted(heading.group(1).strip() if heading else slug)}])")
             primary = specs.line_value(text, "Actor")
             if primary:
                 edges.append(f"  {actor(primary)} --> {ids[slug]}")
             edges += [f"  {ids[slug]} --> {actor(name)}" for name in specs.line_values(text, "Secondary actors")]

                           for other in specs.line_values(text, key) if other in ids and other != slug]
         lines = ["flowchart LR", "  classDef actor fill:none,stroke-width:3px",
                  *(f"  {node}[{_quoted(label)}]" for node, label in actors.values()),
                  f"  subgraph system[{_quoted(capability)}]", *nodes, "  end", *edges]
         if actors:
             lines.append(f"  class {','.join(node for node, _ in actors.values())} actor")
         return "\n".join(lines)
