# Plan: gin-qa re-runs only what a change needs, and never shows an old result as current

Epic: gin-workflow-4706
Workflow: gin-workflow-4706
Spec: `.planning/specs/2026-11-19-qa-rerun-design.md`

## Objective

Every recorded case result carries a `Checked:` stamp of the case as it was; a result whose case or requirement changed since reads as `outdated` in the export and the report. `gin-qa cases due` lists the manual cases a tester needs to run (not run, outdated, failed, blocked, plus a regression set declared by priority in the guidelines), and `/gin-qa:run` walks only those unless asked for `--all`.

## Global Constraints

Copied from the spec:

- Every recorded result is stamped with the case's state at the time; an old result whose case changed since, or whose requirement changed since, reads as `outdated`.
- `/gin-qa:run` runs only what needs running by default (not run, outdated, failed, blocked, plus the regression set); `--all` runs everything as today; `--change <epic>` narrows to the cases pinned to that change's added or modified requirements.
- The regression set is declared in the guidelines by priority (`Regression: none | high | high+medium`, default `none`).
- `Checked` never changes a case's `hash8`; `outdated` is computed at read time and never written; results recorded before this change read `outdated` only when the case is stale. Export keeps every existing key.
- Out of scope: selecting cases for changes that touch no requirement, how `gin-qa e2e`/`gin-qa tests` choose what to run, gin-console.

## Requirement Analysis
- Problem statement: `/gin-qa:run` walks every manual case; a stale, re-pinned, or edited case keeps showing its old `passed`.
- Success criteria: US-1 and US-2 pass as tests; existing gin-qa tests pass; full suite green.
- Constraints: Global Constraints above.
- Non-goals: the out-of-scope list above.

## Approach Options
### Option 1: Stamp at write time, compute at read time (confirmed at discuss)
- Summary: `Checked:` written by `record_result`; `effective_result` compares it and the pins with the current state.
- Pros: catches hand edits of a case; no file rewrites on pin; one writer.
- Cons: old results carry no stamp, so only staleness marks them.

### Option 2: Reset `Result` on pin
- Summary: `cases pin` writes `Result: not run`.
- Pros: simple.
- Cons: misses hand edits of steps; rewrites files; rejected at discuss.

### Recommended Approach
- Selected option: Option 1.
- Rationale: confirmed by the user; it covers every way a case can change.

       def stamp8(case: Case) -> str:
           """The case as a result was recorded against: its hash8 and its pins (or its Source)."""

       def effective_result(case: Case, current: Mapping[str, str] | None) -> str:
           """The result as it stands now: outdated when the case or a pinned requirement changed since it was recorded.

           result = case.fields.get("Result", "not run")
           if result not in ("passed", "failed", "blocked"):
               return result
           stale = current is not None and any(current.get(req) != pinned for req, pinned in case.reqs)
           checked = case.fields.get("Checked")
           return OUTDATED if stale or (checked is not None and checked != stamp8(case)) else result
       ```

     MANUAL_RUNS_SECTION = "## Manual runs"
     REGRESSION_LEVELS = {"none": (), "high": ("high",), "high+medium": ("high", "medium")}
     _REGRESSION = re.compile(r"^- Regression:\s*`?([^`\s]+)`?")


     def regression_level(root: Path, guidelines: str) -> tuple[str, list[str]]:
         """The `- Regression:` level under `## Manual runs` (none when absent), and a finding for a bad value."""
         path = root / guidelines
         lines = [line.rstrip() for line in _lines(path)] if path.is_file() else []
         start = next((index for index, line in enumerate(lines) if line == MANUAL_RUNS_SECTION), None)
         for index in range(start + 1, len(lines)) if start is not None else ():
             if lines[index].startswith("## "):
                 break
             found = _REGRESSION.match(lines[index])
             if found:
                 if found.group(1) in REGRESSION_LEVELS:
                     return found.group(1), []
                 return "none", [f"{guidelines}:{index + 1}: Regression must be none, high, or high+medium"]
         return "none", []


     def due(cases: list[Case], capability: str, current: Mapping[str, str] | None, level: str,
             change_reqs: set[str] | None, everything: bool) -> list[dict[str, str]]:
         """The manual cases of `capability` to run, each with why: todo, regression, or all."""
         rows = []
         for case in sorted((c for c in cases if c.cap == capability and c.type == "manual"), key=lambda c: c.id):
             effective = effective_result(case, current)
             in_change = change_reqs is None or any(req in change_reqs for req, _ in case.reqs)
             if everything:
                 reason = "all"
             elif in_change and effective in ("not run", OUTDATED, "failed", "blocked"):
                 reason = "todo"
             elif case.fields.get("Priority", "") in REGRESSION_LEVELS[level]:
                 reason = "regression"
             else:
                 continue
             rows.append({"id": case.id, "title": case.title, "reason": reason, "effective_result": effective,
                          "priority": case.fields.get("Priority", "")})
         return rows
     ```
