# Plan: tech-doc project blueprint — `FEATURES.md` and `API.md`

## Goal

`/tech-doc` writes two more canonical files: `API.md` (the endpoints the repository exposes, one row each with handler `file:line` and auth) and `FEATURES.md` (feature catalog plus a Feature → Frontend → API → Backend → Data map and coverage gaps). Spec: `.planning/specs/2026-10-06-tech-doc-blueprint-design.md`.

## Architecture

Skill text and templates only. Two new templates under `plugins/gin-workflow/src/templates/codebase/` are served by the existing `template_text()` lookup (`plugins/gin-workflow/src/scripts/workflow_core/specs.py:94`), so `gin-workflow specs template codebase/<FILE>.md` works with no code change. `skills/tech-doc/SKILL.md` gains two split-set rows, the `INTEGRATIONS`/`API` boundary, endpoint and frontend-call discovery, and a completeness check. Docs that enumerate the set are updated. `dist/` is regenerated by `install.sh`.

## Tech Stack

Markdown, Python 3 `unittest`, Bash smoke test. No new tooling or dependencies.

## Global Constraints

Copied from the spec: The change is limited to the skill text, two new templates, one template edit, docs, and packaging tests. No new Python code. Out of scope: a CLI or static parser that extracts routes; request and response schemas or field lists in `API.md`; fixing the gaps the check reports; changes to the other six codebase files beyond the `OVERVIEW.md` link.

## Model Guidance

- `default_model_class`: `standard_impl`; review `high_reasoning`; docs `cheap_simple`.

## Requirement Analysis

- Problem: tech-doc output has no feature view, no exposed-API list, no FE↔BE mapping.
- Success criteria: both templates are served by `specs template`; packaging includes them; the skill tells the agent how to fill them, when to skip `API.md`, and how to check completeness; docs list ten files; full suite and smoke test pass; manual runs on a full-stack repository and on gin-workflow behave as the spec's Testing section says.
- Non-goals: see Global Constraints.

## Recommended Approach

Option A + completeness check from the discussion (skill + templates, no extractor CLI). Chosen and confirmed in `discuss`.

execution_strategy:
