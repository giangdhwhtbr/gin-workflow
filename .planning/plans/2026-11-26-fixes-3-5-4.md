## Approach Options
### Option 1: one track per issue on one branch, sequential, then a release track
- Summary: nine fix tracks in issue order of risk, each its own commit and review, then Track 10 bumps the version and writes the changelog.
- Pros: each fix is reviewed and reverted alone (spec rollback); shared docs files (`docs/reference/cli.md`) never conflict.
- Cons: no parallel execution.

### Option 2: parallel worktrees per track
- Summary: independent tracks run together in their own worktrees.
- Pros: faster wall-clock.
- Cons: Tracks 1, 4, 6, 7, 8, 9 all edit `docs/reference/cli.md`; merges conflict; solo work gains little.

### Recommended Approach
- Selected option: Option 1.
- Rationale: solo work, small tracks, shared docs files.
