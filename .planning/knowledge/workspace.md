# Multi-repo workspace: a parent repository lists child repositories in workspace.repos

**Context**
Epic `gin-workflow-workspace` (discussed and shipped 2026-11-07 to 2026-11-08). A brownfield modernization made of many repositories (frozen legacy, several services, several apps, automation tests, a shared Beads repository) had no home in gin: run from a parent, every track got a worktree of everything; run from a child, gin found no config, specs or beads. The shipped guide recommended `git subtree` into one repository, which does not fit services that deploy independently. Git submodules were rejected in discuss: pointer bumps with no consumer, a parent that is always dirty, and `git worktree` not carrying submodules.

**Decision/Solution**
- The parent is the workspace: `.agent-workflow/config.yaml` gains `workspace.repos` (`path`, `url`, `shape` in frontend, backend, library, qa, beads; `frozen`; `default_branch`; `verify.checks`), validated by `schemas._WORKSPACE` and `workspace.repos_from` (relative paths, no `..`, `.planning` and `.agent-workflow` reserved, no duplicate or nested paths, `beads` only at `.beads`, unknown check names refused, malformed blocks raise `WorkspaceError`). Child repositories are plain clones at their manifest path, gitignored by `/<path>` lines.
- `workspace.locate(given)` returns `Located(root, repo, workspace, entry)`: the main checkout of the enclosing repository (so a linked worktree anywhere resolves to its checkout) is matched against the manifest of each parent directory; outside a child the root is the directory given (today's behaviour, also for a linked worktree of the parent itself). `workspace.repository_root(value)` resolves only the default `--repository`; an explicit value is taken as given. Every CLI entry point (lifecycle, setup, routes, milestone, team, specs, usage, verification, docs, goal, reviewer, rules, notify) applies it; `tasks.main` runs `bd` with cwd at the workspace root. `WorkspaceError` is caught in `cli.main` (exit 2) and in `lifecycle_cli._call` (status error JSON).
- `gin state --format json` gains `workspace: {root, current_repo, repos: [{path, shape, frozen, present, branch}]} | null` (additive for gin-console).
- Since `gin-workflow-ws-entry-rules` (2026-11-14), `workspace` also carries `current: {path, shape, checks} | null` for the entry the command runs in; `project.*` stays the parent's, so skills read the entry's shape and checks from `workspace.current`. One helper, `workspace.current(cwd)` (`Current(located, checkout)`, checkout = the git top level of cwd in a child or its worktree), drives the child path of `gin evidence run/check` (checks that checkout, records in the parent's log), `gin rules` (parent `rules.packs` plus the entry's `rules: {packs}` via `rules.entry_config`, project rules and paths of the child), and `gin setup doctor` (entry checks, hooks, rules; the workspace section proposes packs per entry and reports a child manifest it cannot read instead of crashing). An explicit `--repository` keeps the old behaviour everywhere. Antigravity workers stopped at `orchestrator.worker.timeout_seconds` (900) on both backend tracks of that epic and left correct partial work that a Claude fallback finished; raise the timeout for tracks of that size.
- `gin workspace clone [PATH ...|--all]` (frozen entries shallow, `.gitignore` kept in step even when a clone fails midway) and `gin workspace status`; `gin setup preset|init --workspace`; `setup doctor` actions `workspace: ...` (missing clone, no checks on a `frontend`, `backend` or `qa` entry, a missing, stale or occupied hook of a cloned entry that has checks with the file to chain into, an unreadable child `.git`, path not ignored, path still in `.gitmodules` by exact match) never flip health; `hooks.findings()` builds the hook messages for the parent and the children (`gin-workflow-ua46`).
- Hooks: `hooks._scoped(root, hook)` returns the scoped commands, the events root and the rigor; inside a child the entry's checks run in the repository the hook fired in (a linked worktree included) and the passing pre-push is recorded in the parent's `events.jsonl` against the child's tree; `gin hooks install|status --all-repos` skip frozen, beads and uncloned entries; `install` keeps a hook owned by another tool (husky), names the file to chain `exec gin hooks run <hook> "$@"` into and exits 1; `status` reports only children with `verify.checks` as `{"repos": {...}, "ok": ...}` (`gin-workflow-ua46`). `quick-check` takes the child's checks and the workspace's rigor.
- `gin worktree create|checkout|cleanup --repository <child>` place the child's worktree under the parent's `.planning/worktrees/<track-id>`.
- Plans in a workspace carry `Repo: <path>` per track (`team.Track.repo`, last field); `record plan-approved` and `gin team check-plan` refuse a missing, unknown, frozen or beads repo and files outside it; `plan-approved` needs the plan file as `--plan` or `--evidence`. `routes resolve` keeps `repo` in the manifest on both the main-harness and the orchestrator paths.
- Skills: setup question 6 and `--workspace`; plan `Repo:`; orchestrate creates the child's `feat/<topic>` and the child worktree; execute defers to the `worktrees` skill section Workspace; ship integrates one repository at a time, the parent last; quick runs from the repository changed.
- Validation on the real qwikfone parent (seven submodules): the first procedure (deinit, `rm -f`, delete `.git/modules`) would have destroyed the embedded Beads database, ignored `.env` files, local-only branches, stashes and nested worktrees. The in-place conversion in spec R15 (`git rm --cached`, move `.git/modules/<name>` to `<path>/.git`, `git config -f <path>/.git/config --unset core.worktree`, `worktree repair`, drop the submodule config) converted all seven with nothing lost; `gin state` from the parent and from `backend` were identical, the backend hook ran `backend:lint` only, and the worktree dry run put each child's worktree under the parent.

**Consequences**
- Operating model, revised by the user on 2026-11-10 (roadmap of the process review, shipped in `gin-workflow-roadmap-areas`): one epic per capability with one track per repository; `area:<name>` belongs to the track (orchestrate labels track beads; roadmap entries list `Tracks:` per `skills/roadmap/references/capability-epics.md`); the confirmed spec is the API contract (`requirement_confirmed` freezes it, no separate contract epic); each capability in a milestone's `Integrates:` gets a `<capability> integration` epic blocked by its build epics. Earlier model, superseded: every roadmap epic stayed inside one area (one child repository) and contract epics closed before the service and UI epics. Unchanged: the tech lead owns the roadmap and milestone reviews; each member picks a ready epic of their area and runs the whole lifecycle on their own machine. Under this model the child `feat/<topic>` that orchestrate creates only on the lead's machine is never needed elsewhere; if a lead orchestrates for others, orchestrate must push it and the member steps are missing (bead `gin-workflow-ua46`).
- A track that changes only the parent (docs) is refused in a workspace because R9 requires `Repo:` on every track; the process review (`gin-workflow-process-review`, shipped 2026-11-10) did not settle it and lists it under its workspace clusters for `/gin:roadmap`.
- The process review found workspace gaps verified in code. Fixed by `gin-workflow-ws-ship-gate` (2026-11-10): `gin team check --gate ship` and `record shipped` used to refuse every child pull request (compared with the parent's `origin` and HEAD); now `team.repo_for_pr` matches the pull request to the parent or a `workspace.repos` entry by `host.repo_id`, and takes HEAD from the working directory when it is that child's checkout or worktree, else the child's checkout; an uncloned child names `gin workspace clone <path>`; frozen and beads entries are not excluded. Requirement, plan, and roadmap gates still compare with the parent. Still open: several pull request URLs per `record shipped` and `team deps` for children (`gin-workflow-ws-branch-model`). gin-qa used to need `.agent-workflow/config.yaml` in the current directory; fixed by `gin-workflow-qa-workspace` (2026-11-11): it reads `root` and `qa_root` from `gin specs reqs` and works in the `shape: qa` child or its worktree (see [gin-qa-qa-home](gin-qa-qa-home.md)). Remaining gap: `gin team init` and hooks write to the parent only. See [process-review](process-review.md).
- `gin-workflow-ua46` (shipped 2026-11-08) closed the qwikfone follow-ups: gin never edits a hook owned by husky, doctor and `install --all-repos` name the file to chain into instead; `hooks status --all-repos` exists; a `library` entry may have no checks; `gin setup --help` and `gin workspace --help` describe their actions. `artifacts.worktrees` never was a config key, so nothing disappeared from the qwikfone effective config. `gin-workflow-e5vs` (shipped 2026-11-08) then made `install --all-repos` report a child whose hooks directory is missing and return the worst single-repository exit code (2 missing, 1 occupied, 0 otherwise; `_INSTALL_EXIT` in `hooks.py`).
- Milestones are sprints and an epic has one parent, so a hard project deadline cannot be a milestone; epic `gin-workflow-57fw` shipped it as a `Deadline:` line in the roadmap and a forecast line in `gin milestone list` (see [milestone-lanes-and-forecast](milestone-lanes-and-forecast.md)).
- Two evidence runs failed on timing-sensitive tests under `-n auto` (`test_native_cli` cancellation, `test_e2e_cli` taken-folder suffix) and passed on rerun; both are unrelated to this epic.
- Budgets after the master merge: plan chain 11,994 of 12,000, execute 11,743, ship 10,580, `worktrees` 3,418 of 6,000.
- Not built: version pinning across repositories, `project.packages` inside a child, submodule support.
