# Multi-repo workspace: a parent repository lists child repositories in workspace.repos

**Context**
Epic `gin-workflow-workspace` (discussed and shipped 2026-11-07 to 2026-11-08). A brownfield modernization made of many repositories (frozen legacy, several services, several apps, automation tests, a shared Beads repository) had no home in gin: run from a parent, every track got a worktree of everything; run from a child, gin found no config, specs or beads. The shipped guide recommended `git subtree` into one repository, which does not fit services that deploy independently. Git submodules were rejected in discuss: pointer bumps with no consumer, a parent that is always dirty, and `git worktree` not carrying submodules.

**Decision/Solution**
- The parent is the workspace: `.agent-workflow/config.yaml` gains `workspace.repos` (`path`, `url`, `shape` in frontend, backend, library, qa, beads; `frozen`; `default_branch`; `verify.checks`), validated by `schemas._WORKSPACE` and `workspace.repos_from` (relative paths, no `..`, `.planning` and `.agent-workflow` reserved, no duplicate or nested paths, `beads` only at `.beads`, unknown check names refused, malformed blocks raise `WorkspaceError`). Child repositories are plain clones at their manifest path, gitignored by `/<path>` lines.
- `workspace.locate(given)` returns `Located(root, repo, workspace, entry)`: the main checkout of the enclosing repository (so a linked worktree anywhere resolves to its checkout) is matched against the manifest of each parent directory; outside a child the root is the directory given (today's behaviour, also for a linked worktree of the parent itself). `workspace.repository_root(value)` resolves only the default `--repository`; an explicit value is taken as given. Every CLI entry point (lifecycle, setup, routes, milestone, team, specs, usage, verification, docs, goal, reviewer, rules, notify) applies it; `tasks.main` runs `bd` with cwd at the workspace root. `WorkspaceError` is caught in `cli.main` (exit 2) and in `lifecycle_cli._call` (status error JSON).
- `gin state --format json` gains `workspace: {root, current_repo, repos: [{path, shape, frozen, present, branch}]} | null` (additive for gin-console).
- `gin workspace clone [PATH ...|--all]` (frozen entries shallow, `.gitignore` kept in step even when a clone fails midway) and `gin workspace status`; `gin setup preset|init --workspace`; `setup doctor` actions `workspace: ...` (missing clone, no checks on a workable entry, path not ignored, path still in `.gitmodules` by exact match) never flip health.
- Hooks: `hooks._scoped(root, hook)` returns the scoped commands, the events root and the rigor; inside a child the entry's checks run in the repository the hook fired in (a linked worktree included) and the passing pre-push is recorded in the parent's `events.jsonl` against the child's tree; `gin hooks install --all-repos` skips frozen, beads and uncloned entries. `quick-check` takes the child's checks and the workspace's rigor.
- `gin worktree create|checkout|cleanup --repository <child>` place the child's worktree under the parent's `.planning/worktrees/<track-id>`.
- Plans in a workspace carry `Repo: <path>` per track (`team.Track.repo`, last field); `record plan-approved` and `gin team check-plan` refuse a missing, unknown, frozen or beads repo and files outside it; `plan-approved` needs the plan file as `--plan` or `--evidence`. `routes resolve` keeps `repo` in the manifest on both the main-harness and the orchestrator paths.
- Skills: setup question 6 and `--workspace`; plan `Repo:`; orchestrate creates the child's `feat/<topic>` and the child worktree; execute defers to the `worktrees` skill section Workspace; ship integrates one repository at a time, the parent last; quick runs from the repository changed.
- Validation on the real qwikfone parent (seven submodules): the first procedure (deinit, `rm -f`, delete `.git/modules`) would have destroyed the embedded Beads database, ignored `.env` files, local-only branches, stashes and nested worktrees. The in-place conversion in spec R15 (`git rm --cached`, move `.git/modules/<name>` to `<path>/.git`, `git config -f <path>/.git/config --unset core.worktree`, `worktree repair`, drop the submodule config) converted all seven with nothing lost; `gin state` from the parent and from `backend` were identical, the backend hook ran `backend:lint` only, and the worktree dry run put each child's worktree under the parent.

**Consequences**
- Operating model agreed with the user: the tech lead owns the roadmap and milestone reviews; every roadmap epic stays inside one area (one child repository) with `area:<name>` and Beads dependencies; contract epics close before the service and UI epics; each member picks a ready epic of their area and runs the whole lifecycle on their own machine. Under this model the child `feat/<topic>` that orchestrate creates only on the lead's machine is never needed elsewhere; if a lead orchestrates for others, orchestrate must push it and the member steps are missing (bead `gin-workflow-ua46`).
- A track that changes only the parent (docs) is refused in a workspace because R9 requires `Repo:` on every track; decide at the process review (`gin-workflow-process-review`).
- `hooks install --all-repos` reports `occupied` where husky owns the hooks (qwikfone backend and frontend) and nothing surfaces it; `hooks status --all-repos` is not implemented; doctor reports a docs-only `library` repo without checks; `gin setup --help` and `gin workspace --help` carry no action descriptions (all in `gin-workflow-ua46`).
- Milestones are sprints and an epic has one parent, so a hard project deadline cannot be a milestone; proposal in epic `gin-workflow-57fw` (a `Deadline:` line in the roadmap, a forecast in `/gin:roadmap` and `gin milestone list`).
- Two evidence runs failed on timing-sensitive tests under `-n auto` (`test_native_cli` cancellation, `test_e2e_cli` taken-folder suffix) and passed on rerun; both are unrelated to this epic.
- Budgets after the master merge: plan chain 11,994 of 12,000, execute 11,743, ship 10,580, `worktrees` 3,418 of 6,000.
- Not built: version pinning across repositories, `project.packages` inside a child, submodule support.
